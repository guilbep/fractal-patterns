# Speed, phase 3: the logo no longer loads the pattern generators

## The change

The site header drew its three marks with `src/logo.ts`.
That file imports `src/fractal.ts`, and so every pattern generator.
All three pages shared that code in one chunk, `SponsorBanner-*.js`.
The Studio and the Builder needed it only to draw a 28 px logo.

Now the header shows the static files `public/favicon.svg`, `public/favicon-studio.svg` and `public/favicon-builder.svg`.
`npm run logo` writes these files from the same functions in `src/logo.ts`.
If a file differs from its function, a test in `src/logo.test.ts` fails.

## How to measure

Run `make perf`.
It builds the site for production and serves it with `vite preview`.
Then it runs Lighthouse (mobile) 3 times per page and prints the median.
All numbers below come from that production build, on the same machine, on the same day.

## Start JavaScript per page

| Page | Before | After |
|---|---:|---:|
| Patterns | 101.80 | 101.12 |
| Studio | 91.77 | 64.68 |
| Builder | 67.74 | 36.88 |

The shared chunk `SponsorBanner-*.js` went from 156.30 kB (60.59 kB gzip) to 77.00 kB (30.43 kB gzip).
The generators moved into the Patterns entry chunk, `index-*.js`.
It went from 106.34 kB (36.95 kB gzip) to 176.02 kB (63.12 kB gzip).

## What the numbers show

The Studio loads 27 kB less gzip JavaScript at start, and the Builder 31 kB less.
The Patterns page loads about the same amount, because it uses the generators.
In Lighthouse, the Studio and the Builder each gained about 150 ms on FCP and on LCP.
The transferred bytes fell by about 25 kB on the Studio and about 29 kB on the Builder.
The Patterns page did not change in a way that the runs can show.
The header now loads two more small SVG files on each page.
They are less than 1 kB each, and the numbers show no cost from them.
Total blocking time varies between runs, so these runs show no gain from it.
Three runs per page is a small sample, so read the timings as a direction.

## Builder libraries on demand

The Builder loaded the Studio motif generators and the SVG importer at start.
It needs them only for "Studio drawings", for an SVG file, or for the "Falling leaves" example.
Now `stamps.ts` keeps the basic stamps and the traced image stamps.
`studio-stamps.ts` and `svg-stamps.ts` load with a dynamic `import()` when they are needed.
The "Examples" select shows a static list from `example-list.ts`.
The example designs in `examples.ts` load when a person chooses one.

### What the numbers show

The Builder loads 12868 gzip bytes less JavaScript at start, about 20 percent less.
Lighthouse counts 14214 fewer bytes for the Builder.
Its script evaluation time fell from 115 ms to 87 ms.
FCP and LCP fell by about 150 ms, but three runs are a small sample.
The bundler now groups the shared code in a different way.
Code that the Studio and the Builder share moved into a new chunk, `model-*.js`.
So the Studio loads one more file, and Lighthouse counts 1893 more bytes for it.
Its start chunks went from 64860 to 66014 gzip bytes.
The Patterns page did not change.
Total blocking time varies between runs on an unchanged build, so we claim nothing from it.
