# Speed, phase 5c: phones, folded sections, Builder coach

## What changed

Phase 5c adds to the three pages:
- a phone layout below 600 px: a fixed bottom bar, a palette sheet, and "Use it" as a bottom sheet,
- a 270 px phone preview that shrinks to a 150 px strip while the page scrolls into the controls,
- folded sections with a summary line on the Patterns tabs,
- the Builder first-run coach.

All of it loads at start. Phase 5c adds no dynamic import.

Two small fixes are in this phase. Form fields stay inside their grid column. The phone preview chips stack, one per row, so the size value does not shift the layout.

## How to measure

Run `make perf`. It builds the site for production, serves it with `vite preview`, and runs Lighthouse (mobile) 3 times per page. The tables give the median.

Start JavaScript is the sum of the gzip sizes (default level) of the script and modulepreload files that each `dist/*.html` lists.

All numbers come from the production build, on one machine, on the same day.

## What the numbers show

Each page loads between 0.8 and 1.6 kB more JavaScript at start. That is the bottom bar, the sheets, the folded sections and the coach.

Each page stays under the phase limit of 2 kB more than the previous phase.

The scores stay at 98 or 99. The layout shift is 0.000 on the three pages. Before the chip fix, Patterns measured 0.007.

The Builder first paint is about 160 ms later than in phase 5b. The largest paint is the same. Three runs on one day are too few to call this a real change.

The total blocking time varies from run to run, also on an unchanged build. These numbers do not prove a change in it.
